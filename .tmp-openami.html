OpenAMI

Thread within ISV Village IOT Metering · EnAccess · E-IOT · NESL

OpenAMI is driving actionable energy telemetry — per-customer reads, credit, tamper, and disconnect semantics operators can bill and act on, not utility-scale archive data alone. Leakage visibility at every part of the system — feeder, branch, and customer — so operators can locate loss and theft, not just see aggregate feeder imbalance. Affordable open stack for mini-grids: vendor-agnostic gateways, MQTT northbound interop, Utility Network asset topology, and operator backends.

Community · Discord

OpenAMI discussions live on the OSEA (Open Source Energy Access) Discord server managed by EnAccess. Join: discord.osea-community.org · how to join ↗. ISV Tech Comm goal: participate more actively — introduce work, answer integration questions, share wiki artifacts.

Program overview: enaccess.org/openami. MeshEMS is software supported by E-IOT for learning that stack in the field — multi-tenant edge IOT Metering at the upstream/downstream boundary, documented openly for community operators. Street EMS is the hardware supported by NESL.

Backends at the aggregation point

MPM Manager, OpenEMS, and SparkNet Hub sit at the same point in the aggregation hierarchy — siblings, not a stack. Do not draw one on top of another.

MPM Manager and OpenEMS are alternative backends: pick one. They are not a combined pair.

OpenEMS is an under-development backend for lightweight village use. Linux end-to-end. Less than 60 days ago (as of Sep 2026) Arila started iterating OpenEMS so a Raspberry Pi meter can be swapped for a first-km fan-in of MeshEMS.

OpenEMS — no support yet

The OpenEMS backend has no support yet for SparkNet aggregation, DLMS/COSEM, or STS. That is a gap, not a working interop matrix. Do not read the chooser below as “any first-km + any hub + OpenEMS.”

Component Role Supported By GitHub Notes

Utility Network Asset topology — villages pack Open GeoJSON pack borrowing Esri Utility Network semantics (not ArcGIS lock-in): structure, devices, junctions, lines, subnetworks, associations.
